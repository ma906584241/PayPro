2026-10-28：使用本次用户上传的 PNG 原图替换支付宝收款码，未重绘、裁剪或压缩二维码。原图尺寸 591 × 576，SHA-256：

## 已更新内容

- [外置收款码](../qr/alipay/custom.png) 与 [打包收款码](../src/main/resources/static/assets/qr/alipay/custom.png) 均为原图。
- 两张旧支付宝 0.01 示例图也替换为同一原图，避免保留指向原收款人的支付宝图片；这些图片现在不代表固定金额码。
- 基础、生产配置的 `alipayCustomQrUrl` 改为原图中解码得到的支付宝链接；支付宝 `use-local-qr-code=true`。
- 充值页默认支付宝使用本地码，提示改为“扫码付款，需填写订单标识”。
- 支付页固定读取新的支付宝通用码，兼容旧链接中的 `useLocalQrCode=false`；图片地址增加内容版本号，避免沿用旧缓存。
- 普通与 OpenAPI 支付宝订单均不进入减额槽位分配，保持请求金额并生成付款标识；OpenAPI 的 qrCodeUrl 指向新通用码。
- 旧 openAlipay 页面保留订单号、金额和备注后跳转到新支付页，不再进入原来的免备注 / 红包收款流程。
- 修复支付页自定义二维码路径的模板字符串插值。

## 使用方式

付款人扫描二维码，输入订单所示金额，并在付款备注填写订单标识。管理员核验到账后审核订单。当前是普通收款码加人工审核，不表示已实现自动到账确认。

## 验证与部署

四个支付宝 PNG 文件的哈希均与原始附件一致，均可解码为同一个支付宝链接。JavaScript 检查覆盖默认支付方式、新旧链接选图、微信自定义码路径和旧支付宝入口重定向。Playwright 本地预览确认 1440px、390px 下图片加载完成，移动端打开链接与原图内容一致，备注提示可见；没有访问收款链接或发起真实支付。

本机没有 java/mvn，Java 服务变更未编译运行。将修改同步到服务器后，在项目目录执行：

```bash
docker compose up -d --build
```

外置 `qr` 与 `config` 目录也必须同步。修改目前仅在本地，线上尚未部署。
