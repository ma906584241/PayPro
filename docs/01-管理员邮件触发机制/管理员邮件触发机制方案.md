# 改为客户确认付款后通知管理员

## 确定的流程

新订单采用：**创建订单不发邮件 → 客户付款 → 点击“我已完成付款”并再次确认 → 通知管理员 → 管理员核实到账并审核**。

客户确认仅代表“声明已付款”，不会直接标记支付成功。旧订单继续使用已经收到的审核邮件处理，不补发通知。

## 实现调整

- 移除普通下单和 OpenAPI 下单时立即发送管理员邮件的逻辑。
- 支付页增加“我已完成付款”按钮。点击后弹出二次确认，取消不发送请求；提交后显示“等待管理员核实到账”，停止付款倒计时，继续查询审核结果。
- 管理员邮件注明“客户声明已付款，待核实”，展示数据库中的订单金额、付款标识和现有审核链接。
- 保留管理员批准、驳回及后续通知流程；同时修复空订单来源和无商品的自定义金额订单无法正常审核完成的问题，不扩展商品交付功能。

## 接口、状态与去重

- 为新订单生成独立的客户确认凭证，仅在数据库保存 SHA-256 哈希；普通及 OpenAPI 下单响应新增 `paymentConfirmToken`，支付链接携带该凭证。管理员 Token 不发送给客户。
- 新增 `POST /order/confirm-paid`，提交订单号与确认凭证；新增 `GET /order/payment-confirmation`，通过请求头携带凭证，查询订单状态、确认时间、通知状态及是否可重试。均复用 `ResponseVO`。
- 订单表新增三个可空字段：确认凭证哈希、客户确认时间、管理员通知状态。旧数据保持空值，识别为旧流程；支付成功等现有状态编号保持不变。
- 使用数据库通知状态配合 Redis 的订单级发送锁去重，锁有效期 120 秒。重复点击、刷新、并发请求不重复发送已成功通知的邮件。
- 邮件在事务提交后异步发送，按真实 SMTP 结果记录成功或失败，不再吞掉发送错误。失败或发送锁超时后，客户可点击“重试通知管理员”；不自动补发旧订单邮件。
- 无效凭证、已终结或明确过期的订单不触发通知。旧链接和缺失凭证的链接不开放确认按钮，提示使用完整新链接或联系客服。

## 验证与上线

- 验证普通及 OpenAPI 下单、打开页面、刷新、查询状态、取消确认均不发送邮件。
- 用 Mock SMTP 验证确认后发信、重复点击去重、失败重试及发送中刷新后的状态恢复。
- 验证客户确认不会触发支付成功、商品交付或商户回调；这些仍需管理员审核。
- 检查支付宝、微信、自定义金额及桌面、手机页面，保持当前二维码和品牌配置。
- 提供独立、仅新增字段的升级 SQL，禁止重跑含删表操作的初始化脚本。先升级数据库，再同时部署后端和页面，并更新接口文档及 CodeGraph。
- OpenAPI 接入方使用新的 `returnUrl`，或在自行拼接支付页时传入确认凭证。现有请求参数及签名算法保持不变。
